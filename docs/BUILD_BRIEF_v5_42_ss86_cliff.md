## 3. The defect

One expression, `<anon>@8719`, the ladder loop — **L8885 in v5.41, re-find with `funcmap.cjs`**:

```js
if (provisional > _ssT2) taxableSS = Math.round(totalSS * 0.85);
```

26 U.S.C. §86(a)(2) does not do this. It phases in:

```
includible = min( 0.85 × SS ,  0.85 × (prov − adjbase) + min( para1 , ½(adjbase − base) ) )
     where para1 = min( ½ × SS , ½ × (prov − base) )
```

The app jumps to the **full 85% of benefits** the instant provisional crosses $44,000, skipping the
entire phase-in. The two converge only at provisional ≈ $92,141 on the example household.

The middle tier (`provisional > _ssT1`) is **correct** and must not be touched. The filing-status
threshold selection via `taxFactsFor(_filingSingleAt(year))` is **correct** (v5.15) and must not be
touched — the single-filer pair must keep flowing through.

## 5. Direction — this one makes the plan look BETTER

Every correction for several releases has been conservative: the plan looked worse afterwards. **This
one goes the other way.** MAGI, taxable income, tax, marginal rate and IRMAA risk all *fall* for
affected households, some of them by a lot, and an IRMAA verdict can flip from triggered to not.

That has to be stated plainly in the CHANGELOG rather than buried: users who had already read their
numbers will see them drop, and they are entitled to know the earlier figure was wrong rather than
the new one being optimistic. The app was overstating taxable Social Security by up to 5.3×.

## 6. Test design — the slider must be driven, and it works

The fix is invisible at the default, so **assertions at the default prove nothing.** The tests must
move the conversion slider. This was proven feasible during scoping, so it is not a research task:

- the control is `<input type="range" min=0 max=400000 step={5000}>` — $15,000 and $20,000 are valid steps;
- it is a **React controlled input**, so assigning `.value` does nothing. Assign through the native
  setter, then dispatch `input`:

```js
const setNative = Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, "value").set;
await act(async () => { setNative.call(slider, "15000"); slider.dispatchEvent(new window.Event("input", { bubbles: true })); });
```

- verified working: driving to 15,000 / 20,000 / 50,000 / 70,000 re-rendered the ladder and produced
  the pre-fix MAGI figures in §4 exactly.
